# Building the Android APK

The app ships as a **Trusted Web Activity (TWA)**: a real Android app whose
only screen is a Chrome-powered fullscreen view of the hosted web app. The
entire Next.js + FastAPI backend stays on your server — nothing runs on the
phone except the browser shell.

## What was added

| File | Purpose |
| --- | --- |
| `app/manifest.ts` | PWA manifest served at `/manifest.webmanifest` |
| `public/sw.js` | Service worker (installs the app icon shell) |
| `components/ServiceWorkerRegister.tsx` | Registers the service worker |
| `public/icons/*.png` | App icons (generated by `scripts/make_icons.py`) |
| `android/twa-manifest.json` | Bubblewrap config |
| `android/assetlinks.json` | Template for Play Store link verification |

## Prerequisites

1. **JDK 17** (`java` on PATH, `JAVA_HOME` set)
2. **Android SDK** (`ANDROID_HOME` set, with `platforms;android-34` and
   `build-tools;34.0.0` installed, licenses accepted)
3. **Node.js 18+**
4. **A deployed, HTTPS URL** for the app (e.g. Vercel/Railway). The TWA loads
   content from this URL, so it must be reachable from the phone.

## Step 1 — Deploy the web app

Deploy the Next.js app and the FastAPI service (Stockfish + Tesseract) so the
site is live at `https://chess.njxai.com`. See `DEPLOY.md` for the Docker +
Caddy steps. Set the usual env vars (`PYTHON_SERVICE_URL`, `DATABASE_PATH`,
Stripe keys) on the server.

Verify the manifest is live:

```bash
curl https://chess.njxai.com/manifest.webmanifest
```

## Step 2 — Point the TWA config at your URL

`android/twa-manifest.json` is already pointed at `chess.njxai.com`. Keep
`packageId` as `com.checkmatecoach.app` (or your own reverse-DNS id).

## Step 3 — Build a debug APK (verified working path)

A debug APK has already been built and copied to
`android/checkmate-coach-debug.apk` (signed with the Android debug key —
installable on any device with "install unknown apps" allowed).

To rebuild it from scratch:

```bash
# 1. Serve the web manifest + icons locally (the generator fetches these)
cd android/local-server
python -m http.server 8788 --bind 127.0.0.1

# 2. In another terminal, generate the Android project
node scripts/build_twa.js http://127.0.0.1:8788

# 3. Build the debug APK with Gradle
cd android/twa-project
gradlew.bat assembleDebug
```

- Debug APK: `android/twa-project/app/build/outputs/apk/debug/app-debug.apk`
- No signing prompts — Gradle uses the debug keystore automatically.

### Toolchain used

- JDK 17 (set `JAVA_HOME`)
- Android SDK (set `ANDROID_HOME`) with `platforms;android-36`,
  `build-tools;35.0.0`, and `build-tools;36.1.0`. Bubblewrap requires
  build-tools `36.1.0` and a `bin`/`tools` folder at the SDK root (a junction
  `bin -> cmdline-tools/latest/bin` satisfies it).

## Step 4 — Production build (needs a live URL)

Once the site is deployed at a real HTTPS URL (update `android/twa-manifest.json`):

```bash
npm install -g @bubblewrap/cli
bubblewrap build --manifest android/twa-manifest.json
```

`bubblewrap build` produces `app-release-bundle.aab` (upload this to the Play
Console) and a signed `app-release-signed.apk`. Set `BUBBLEWRAP_KEYSTORE_PASSWORD`
and `BUBBLEWRAP_KEY_PASSWORD` to sign non-interactively.

## Step 4 — Play Store link verification (release only)

After the release key is created, get its SHA-256 fingerprint:

```bash
keytool -list -v -keystore android.keystore | grep SHA256
```

Paste the fingerprint into `public/.well-known/assetlinks.json` (the web app
serves it automatically) at:

```
https://chess.njxai.com/.well-known/assetlinks.json
```

## Notes

- **Billing:** Play policy requires Google Play Billing for the $20/mo
  subscription sold inside the Play app. Keep Stripe for the web/PWA and add
  Play Billing (or a web-first signup flow) before a Play Store launch.
- Regenerate icons anytime with:
  `python scripts/make_icons.py`.
